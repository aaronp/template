Template repository · docs-as-code

Every project artifact.
One repo.

Goals, architecture, decisions, risks, interfaces, schedule and the work itself — kept as plain Markdown and JSON next to the code, reviewed in pull requests, and rendered by small web tools that read straight from this repo.

Dashboard A filled-in Acme example: every area at a glance. Walkthrough Eight yes/no questions, one card each.

Why

01

One place, so projects stay small

Goals, risks, rationale and the schedule change together as a project evolves, so they live together, right beside the code. Keeping them current takes minutes, which makes it cheap to start small, scope tightly and see when scope drifts.

02

A clear view for the whole team, human or AI

Everyone working on the project, people and AI agents alike, reads the same goals, plan, risks and decision log: plain text in the repo, searchable with grep, with the history of how each one got there.

03

Data, not software

The project data is nearly all Markdown. The tools here are optional viewers: use them, use your own, or add and drop areas as the project needs. The data stays yours and outlives any tool.

How it works

01

Write it as plain text

Each area is a Markdown or JSON file with a simple, documented shape. No database, no SaaS account.

02

Commit it next to the code

Changes to a risk or a decision go through the same pull request, review and history as the code they affect.

03

Open it in a tool

Every tool takes a ?src= pointing at a file in this repo.

https://aaronp.github.io/risk-register/?src=https://raw.githubusercontent.com/aaronp/template/main/docs/risks/risks.md

Use this template

Create an empty repo on GitHub, then copy the template into it. You get the dashboard and walkthrough with your repo's name and links; this page is left behind.

git clone {{templateUrl}}.git
cd template
make clone        # asks for owner/repo and a project name
project-template Plain Markdown and JSON. Rendered by tools that take ?src=. {{templateUrl}}
